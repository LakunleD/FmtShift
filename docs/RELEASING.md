# Releasing FmtShift

FmtShift links libvips dynamically and does not bundle it (packaging
decision, ARCHITECTURE.md §11). A release therefore consists of:

| Platform | Artifact | Users install libvips with |
|---|---|---|
| macOS (and Linuxbrew) | Homebrew formula building from the tagged source | Homebrew (`depends_on "vips"`) |
| Linux amd64 / arm64 | `fmtshift_<version>_linux_<arch>.tar.gz` | apt / dnf (see README) |

Each archive contains the `fmtshift` binary, `LICENSE`, `README.md` and
`THIRD_PARTY_LICENSES` (generated by `scripts/third-party-licenses.sh` from
the modules actually linked). `SHA256SUMS` covers all archives.

## One-time setup: the Homebrew tap

Create a public GitHub repository named **`homebrew-tap`** under the same
account (`github.com/lakunled/homebrew-tap`) with an empty `Formula/`
directory. Users then install with:

```sh
brew install lakunled/tap/fmtshift
```

## Steps for each release

1. **Check main is green.** The CI workflow must pass on Linux and macOS.

2. **Dry run.** In GitHub → Actions → *Release* → *Run workflow* on `main`.
   This builds and tests everything without publishing:
   - Linux archives built on native amd64 and arm64 runners after `make check`;
   - each archive smoke-tested in clean `ubuntu:24.04` and `debian:trixie`
     containers with only the documented runtime packages installed;
   - the Homebrew formula installed from source on macOS, `brew test` and
     `brew audit --strict --new`. A dry run renders the formula for GitHub's
     archive of the commit being tested (so it must be pushed) with an
     explicit `version "0.0.0"`, since a commit hash carries no version. Tag
     releases omit the version line; Homebrew infers it from the tag.

3. **Tag and push.**

   ```sh
   git tag -a v0.1.0 -m "FmtShift v0.1.0"
   git push origin v0.1.0
   ```

   The workflow repeats the dry run against the tag and creates a **draft**
   GitHub release with the archives, `SHA256SUMS` and `fmtshift.rb` (the
   formula rendered for the tag's source archive).

4. **Review and publish the draft** on GitHub: edit the generated notes,
   check the assets, then publish.

5. **Update the tap.** Download `fmtshift.rb` from the release and commit it
   to the tap as `Formula/fmtshift.rb`:

   ```sh
   cd homebrew-tap
   cp ~/Downloads/fmtshift.rb Formula/fmtshift.rb
   git commit -am "fmtshift 0.1.0" && git push
   ```

6. **Verify on a clean machine** (or a fresh user account):
   `brew install lakunled/tap/fmtshift && fmtshift convert some.heic`.

## Building an archive locally

```sh
make dist VERSION=v0.1.0   # dist/fmtshift_v0.1.0_<os>_<arch>.tar.gz + .sha256
```

macOS archives are not published: a binary built against Homebrew's libvips
hard-codes Homebrew's library paths, so macOS users install via the formula.

## Licensing notes

- FmtShift is MIT licensed. Release archives contain only FmtShift and the
  Go modules it links (Apache-2.0 and BSD-3-Clause, plus Go's BSD licence),
  listed in `THIRD_PARTY_LICENSES`.
- libvips (LGPL-2.1+), libheif (LGPL-3.0+), libde265 (LGPL-3.0+) and the
  other image libraries are installed by Homebrew or the distribution, not
  shipped by FmtShift. FmtShift does not distribute an HEVC decoder or the
  GPL x265 encoder.
- If a future release bundles libvips (e.g. self-contained archives), the
  LGPL obligations, a decode-only libheif without x265, and HEVC patent
  considerations must be reviewed first.
